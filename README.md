# Bet Scanner V0.1

A local football betting-market research dashboard. It scans ten entirely fictional opportunities, calculates value, filters by a minimum probability edge, and ranks candidates by expected ROI.

**SIMULATION / MOCK DATA:** teams, fixtures, odds, and hand-assigned model probabilities are fictional. Results are not real betting recommendations. No bookmakers, external APIs, AI services, authentication, database, or bet placement are involved. The app uses system fonts and needs no external assets.

## Run locally

```sh
pnpm install
pnpm dev
```

Open http://localhost:3000. Use the minimum-edge input to apply a new threshold in percentage points; Reset restores the default of 2 pp. A threshold of 100 pp demonstrates the `NO BET` state.

## Analysis

Only `MATCH_WINNER` is supported, with `HOME`, `DRAW`, and `AWAY` selections. Odds are decimal; probabilities and thresholds are fractions between 0 and 1 internally.

- Implied probability: `1 / decimalOdds`
- Edge: `modelProbability - impliedProbability`, displayed in percentage points
- Expected ROI: `modelProbability * decimalOdds - 1`, displayed as a percentage
- Qualification: `edge >= minimumEdge`, default `0.02`
- Ranking: expected ROI descending; exact ROI ties use ascending opportunity ID

For odds `2.14` and model probability `0.50`, expected ROI is `0.07` (7%). The implied probability is a raw price conversion, without a bookmaker-margin adjustment.

Non-finite odds, odds ≤ 1, and probabilities or thresholds outside [0, 1] throw `RangeError`. A scan fails explicitly on invalid data instead of omitting it silently. Filtering allows one machine epsilon of subtraction noise at the inclusive threshold boundary; calculations are never rounded before ranking or filtering.

At the default threshold, 5 of the 10 opportunities qualify. Eastford United is first with 18.4% expected ROI. These probabilities are supplied mock inputs, not predictions generated by an actual model.

## Structure

- `src/data/mock-markets.ts`: fictional input dataset
- `src/lib/betting/types.ts`: opportunity and analysis types
- `src/lib/betting/analyse-bet.ts`: pure calculations and input validation
- `src/lib/betting/rank-bets.ts`: pure filtering and deterministic ranking
- `src/app/page.tsx`: passes the dataset to the dashboard
- `src/app/scanner-dashboard.tsx`: local threshold state and results UI
- `src/lib/betting/*.test.ts`: core unit tests

The existing Next.js App Router and TypeScript setup are retained. A small client component applies filters in memory; no API routes or persistence are needed.
